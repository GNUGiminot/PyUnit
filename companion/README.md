# companion — новый интерфейс и счётчик сушек для PyUnit

> English: a drop-in companion for [xatang/PyUnit](https://github.com/xatang/PyUnit).
> It adds a dial-gauge UI, a drying counter and a PWA without touching the PyUnit image.

Надстройка над PyUnit: отдельные контейнеры рядом с ним. Сам PyUnit остаётся
как есть и работает на `:5000`, новый интерфейс — на `:5001`.

```
Телефон / ПК
   │
   ├─ :5001 ─► dryer-ui (nginx) ──┬─ /            новый интерфейс (HTML+JS, без сборки)
   │                              ├─ /api, WS ───► pyunit:5000
   │                              └─ /stats ─────► dryer-stats
   │
   └─ :5000 ─► pyunit  (оригинальный интерфейс — всё редактирование и настройка)
                  └─► Moonraker :7125 ─► Klipper ─► нагреватель, сервопривод, SHT3x, вентилятор
```

## Что внутри

| Путь | Назначение |
|---|---|
| `web/` | Новый интерфейс: кольцевые шкалы, самописец, пресеты, таймер, счётчик, PWA |
| `stats/` | Сервис счётчика сушек (Python, только стандартная библиотека) |
| `nginx/` | Конфиг прокси: интерфейс, `/api` + WebSocket, `/stats` |
| `docker-compose.companion.yml` | Отдельный compose-проект |
| `legacy-overlay/` | CSS-тема и кнопка «← Новый интерфейс» для оригинального интерфейса |

Исправления самого бэкенда PyUnit лежат в `api/` и описаны в коммите
`fix: безопасность нагрева и гонки состояний…`.

## Запуск

Каталог `companion/` должен лежать внутри каталога PyUnit (рядом с `pyunit.db`):
пути к базе в compose заданы относительно него.

```bash
cd <каталог-PyUnit>/companion
docker-compose -p dryer-companion -f docker-compose.companion.yml up -d --build
```

Откат — `down` с теми же аргументами. PyUnit при этом не затрагивается.

Без устройства интерфейс можно посмотреть на встроенном симуляторе: откройте
`web/index.html?demo=1` (любым статическим сервером) — приборы работают на
сгенерированных данных.

## Как работает счётчик

PyUnit при **каждом запуске** стирает таблицу `dryer_logs`
(`CLEAR_LOGS_ON_STARTUP=True` в `.env`), поэтому история сушек в его базе не
живёт. `dryer-stats` раз в 5 с читает свежие строки (только чтение, URI
`mode=ro`), восстанавливает сессии и хранит их в **своей** базе (том
`stats_state`). История копится только пока сервис работает.

Сессия — от первого статуса не-`pending` до:

- перехода в хранение → завершена;
- остановки с остатком времени → прервана;
- `pending` после обнуления таймера → завершена.

Время хранения сушкой не считается, сессии короче минуты отбрасываются.

## Таймер

Отсчёт `dry_time` в PyUnit начинается **не с нажатия «Запустить»**, а когда
влажность впервые достигла цели пресета. До этого идёт прогрев, поэтому
реальная длительность всегда больше `dry_time`. Интерфейс показывает это
явно: на прогреве — время с запуска, на выдержке — «прошло / осталось /
готово в ЧЧ:ММ».

## Установка на Android как приложения

Манифест и service worker есть, но по обычному `http://` Chrome не считает
origin безопасным и ставит только ярлык. Один раз на телефоне:
`chrome://flags/#unsafely-treat-insecure-origin-as-secure` → добавить
`http://<адрес-устройства>:5001` → Enabled → перезапустить Chrome → меню →
«Установить приложение».

## Старый интерфейс

`legacy-overlay/` — необязательная CSS-тема для оригинального интерфейса
(на `:5000`) и кнопка возврата в новый. Подключается через
`docker-compose.override.yml` с монтированием `:ro`, образ не пересобирается;
готовый пример — `legacy-overlay/docker-compose.override.example.yml`.

## Известные особенности

- На некоторых хостах `docker-compose` 1.29 несовместим с Docker Engine 28:
  `up -d` на **существующем** контейнере падает с `KeyError: 'ContainerConfig'`,
  успев остановить и переименовать его. Обход: `docker rm <хэш>_pyunit`, затем
  `up -d`. Компаньон на это не влияет — он создаётся с нуля.
- На устройствах без RTC (Orange Pi) часы врут до синхронизации NTP, поэтому
  первые строки телеметрии после загрузки могут иметь неверное время.
  Счётчик это учитывает: если самая свежая метка старше сохранённой, считается,
  что база была очищена.
